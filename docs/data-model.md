# 一期一会 v2 — データの形

> 設計方針は `docs/redesign.md`、SQL は `v2/supabase/schema.sql`。
> ルールの検証は `bash v2/supabase/tests/run.sh`（ローカルの PostgreSQL 16 で実行）。

## テーブル（7つ）

```
profiles ─┬─< albums ──< album_members >── profiles
          │      └────< album_invites
          └─< memories ──< messages
                  └─────< unlocks（訪問写真つき）
```

| テーブル | 中身 | 主な列 |
|---|---|---|
| `profiles` | 利用者 | 表示名、タイムゾーン、写真の上限枚数 |
| `albums` | アルバム（1階層） | 名前、持ち主 |
| `album_members` | アルバムのメンバー | 役割（owner / editor / participant） |
| `album_invites` | 招待リンク | トークン、付与する役割、取り消し日時 |
| `memories` | 思い出（写真1枚と場所） | 写真のパス、緯度経度、撮影日時、アルバム（null = 未整理） |
| `messages` | 元のメッセージと追記 | 本文、元のメッセージか、封をした日時（null = 下書き） |
| `unlocks` | 解除の記録（訪問） | 解除した日時、訪問写真のパス（任意） |

旧設計の15本のマイグレーションに対して、1本にまとまっています。

## ルールの実現方法

| ルール | 実現方法 |
|---|---|
| 下書きは自分だけが読めて書き直せる | `messages` は自分が書いた下書きだけを直接読み書きできる |
| 封をすると自分も読めない | 封は `seal_message()` で行い、日時は DB が `now()` で決める。封をした行は、トリガーで変更を禁止する |
| 翌日以降の解除で読める | 「解除した日 > 封をした日」を、読む人のタイムゾーンの日付で比べる（`can_read_sealed`） |
| ロック中でも件数は見える | `memory_messages()` が、ロック中の行は本文を空にして返す |
| 他人の下書きは見えない | 他人の下書きの思い出・メッセージは、存在ごと返さない |
| 解除は現地での判定を通したときだけ | `unlocks` には利用者が書き込めない。解除用の Edge Function（service role）だけが記録する |
| 共有アルバムから外すと読めない、戻すと読める | 解除の記録は消さず、「今その思い出が入っているアルバムのメンバーか」を毎回判定する |
| 写真の上限（今持っている枚数） | 思い出の写真と保存した訪問写真を数え、追加時にトリガーで確認する。訪問写真を消すと枠が空く |
| 写真・場所・撮影日時は変えられない | `memories` で利用者が変えられるのは `album_id` だけ |

## 操作用の関数

| 関数 | 用途 |
|---|---|
| `seal_message(id)` | 下書きに封をする |
| `memory_messages(memory_id)` | 思い出のメッセージ一覧（ロック判定つき） |
| `accept_invite(token)` | 招待リンクでアルバムに参加する |
| `my_photo_usage()` | 自分の写真の枚数と上限 |

これ以外の関数は、アクセスルールやトリガーの中だけで使い、アプリから直接は呼べない。ログインしていない人は、どの関数も呼べない。

## まだ決めていない・後で作るもの

- **Storage**：写真は非公開のバケットに置き、`can_view_memory()` と同じ条件で読めるようにする（旧設計は公開バケットだった）
- **解除用の Edge Function**：位置の確認、AI 判定、`unlocks` への記録、訪問写真の保存（次の段階）
- **アルバムの持ち主が、他の人の思い出をアルバムから外せるか**：今は思い出の持ち主しか外せない
- **写真の上限の値**：仮に30枚。プランが決まったら変える
