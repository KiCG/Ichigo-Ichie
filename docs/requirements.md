1. プロジェクト概要
### 「その時、その場所で、何を思った？」
本プロジェクトは、過去に写真を撮った同じ場所（位置情報）で、再び同じ風景（画像認識）を撮影したときにだけ、過去の自分が残したメッセージ（日記）のロックが解除される「思い出記録・追体験アプリ」である。

2. ユーザーシナリオ
観光客の備忘録と再訪: 旅先で写真を撮りメッセージを保存。後日写真を見て再訪を促され、再び訪れた際に過去のメッセージを見て懐かしむ。

親しい友人・カップル間の共有: アルバムを共有し、互いに思い出の場所を訪れてメッセージを読み合い、追記して楽しむ。

著名人・クリエイターの聖地巡礼: ファンに向けて特定の場所のアルバムを共有。ファンは実際にその場所に足を運ぶことで（クエスト形式）、特別なメッセージを閲覧できる。

3. 技術スタック
フロントエンド: React Native (Expo) + TypeScript

バックエンド / データベース: Supabase (PostgreSQL, Auth, Storage)

画像認識AI: Google Gemini API (Gemini Flashモデル) - APIキー保護のため、クライアントから直接呼び出さずSupabase Edge Functions経由で呼び出すこと

位置情報・カメラ: Expo Location, Expo Camera

4. 主要機能要件
### 4.1. 撮影＆記録機能（思い出の保存）
デバイスのカメラを用いた写真撮影。

- 撮影時のGPS位置情報（緯度・経度）と日時をバックグラウンドで自動取得し、写真データに紐付ける。

- 写真に対するメッセージ（日記）の入力・保存。

tmpアルバム仕様:
- 撮影した写真はまずtmpアルバムに保存され、ユーザーが落ち着いた場所でメッセージを書いてから正式なアルバムへ移動する。
- tmpアルバムへの保存枚数は無制限。旅行中など大量に撮影した場合でも制限なく一時保存できる。
- メッセージが書かれていない写真は撮影から3日後に自動削除される。削除24時間前にプッシュ通知で警告する。
- カメラロールへの自動保存設定を用意する。以下の3択から選択可能（デフォルト:「全ての写真」）。
  - 全ての写真: tmpアルバムの写真を含め、アプリで撮影した写真を全てカメラロールに保存する。
  - メッセージ付きの写真のみ: 正式なアルバムに保存された写真のみカメラロールに保存する。
  - 保存しない: カメラロールへの保存を行わない。

### 4.2. ロック解除機能（思い出の追体験）
- 複雑な判定ロジックを秘匿し、ユーザーには直感的に扱える魔法のような体験を提供する。

解除フロー:
1. ユーザーが解除カメラを起動する。
2. 現在地から半径50m以内の写真をDBで絞り込む（距離計算のみ、API不要）。
3. 候補0件の場合 → 「この場所の思い出はありません」を表示。
4. 候補1件の場合 → 自動でAI判定へ進む。
5. 候補複数の場合 → ぼかしたサムネイルを表示しタップさせた後、AI判定へ進む。

条件1（位置情報）: ユーザーの現在地が、対象の写真が撮影された地点から指定の半径（例: 50m）以内であること。

条件2（画像認識）: その場でカメラを起動し撮影した画像と、過去の画像の「背景・ロケーション」が一致していることをAIで判定する（Supabase Edge Functions経由で呼び出す）。

AIプロンプト定義: 「昼夜の違い、季節の違い、手前の人物や障害物の違いは完全に無視し、建物や風景のロケーション（背景）が同一であるかのみを判定してください。」

- ロック解除成功後、過去のメッセージの閲覧および、新たな追記が可能になる。

### 4.3. アルバム＆本棚機能
アルバム機能: 写真とメッセージをグループ化。一覧画面では写真は常に表示（宝の地図としての役割）され、メッセージ部分のみ鍵アイコン等でロックUIを表示する。

本棚機能: 複数のアルバムをまとめる。

ソート機能: MVP段階では不要と判断し省略。アルバム・本棚による手動整理で代替可能。

現在地から近い写真の表示: ロック解除フローの入口として必須のコア機能。「近くにロックされた思い出がある」と気づくことが再訪の動機となるため、地図またはリスト形式で現在地周辺のロック済み写真を表示する画面を設ける。

### 4.4. 共有機能
- アルバム単位での他ユーザーへの共有（リンクまたはID）。

権限設定: 「閲覧のみ」「編集可（追記可能）」を選択可能。

ロック仕様: 共有された側のユーザーも、実際に現地へ行き、同じ条件（位置情報＋画像）をクリアしない限りメッセージを読むことはできない。

5. UI / UX 設計方針
コンセプト: アナログな温かみ（ノスタルジック）やすりガラス効果（クリア・ギャラリー）など、エモーショナルな体験を強調するデザイン。

オーバーレイ機能: 廃止。AIは構図の一致を要求せず背景・ロケーションのみを判定するため、構図合わせのサポートは不要。また撮影体験を阻害するリスクがあるため削除。

- 後ほど画像素材を用いて変更する予定なので、変更しやすい設計にすること

7. データベース設計 (Supabase)
※ Supabase Authが管理する auth.users テーブルが認証情報の正とする。public.users.id は auth.users.id と一致させること。

1. users テーブル

- id (UUID, PK - auth.users.id と一致)

- name (String)

- plan_type (Enum: 'free', 'premium', 'pro')

2. bookshelves テーブル ※新規追加

- id (UUID, PK)

- user_id (UUID, FK)

- title (String)

- created_at (Timestamp)

3. albums テーブル

- id (UUID, PK)

- bookshelf_id (UUID, FK, nullable) ※追加

- user_id (UUID, FK)

- title (String)

- cover_photo_id (UUID, FK, nullable) ※追加: 本棚一覧のサムネイル用

- created_at (Timestamp)

4. photos テーブル

- id (UUID, PK)

- album_id (UUID, FK)

- user_id (UUID, FK) ※追加: 投稿者を直接特定するため

- image_url (String - Storageへのパス)

- latitude (Float - 緯度)

- longitude (Float - 経度)

- taken_at (Timestamp)

5. messages テーブル

- id (UUID, PK)

- photo_id (UUID, FK)

- content (Text)

- author_id (UUID, FK)

- is_original (Boolean) ※追加: 撮影時の初回メッセージか追記かを区別

- created_at (Timestamp)

6. unlock_records テーブル ※新規追加: ロック解除状態の永続化

- id (UUID, PK)

- user_id (UUID, FK)

- photo_id (UUID, FK)

- unlock_image_url (String, nullable - 解除時に撮影した写真のStorageパス)

- unlocked_at (Timestamp)

7. album_shares テーブル

- id (UUID, PK)

- album_id (UUID, FK)

- shared_by_user_id (UUID, FK) ※追加

- shared_to_user_id (UUID, FK, nullable) ※リンク共有時はnull

- share_token (UUID, nullable) ※追加: リンク共有用トークン

- permission (Enum: 'read_only', 'can_edit')

- shared_at (Timestamp) ※追加
